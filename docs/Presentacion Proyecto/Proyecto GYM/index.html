GYMETRA-PRIN: Gestión de Membresías de Gimnasio 🏋️‍♂️

Presentación del Proyecto

Este sistema gestiona de manera integral las operaciones de un gimnasio: desde el registro de usuarios y la administración de membresías hasta el control de accesos y la gestión de pagos. Incluye módulos de autenticación y seguridad, administración de membresías, procesamiento de pagos, validación de accesos mediante códigos QR, generación de reportes administrativos y envío de notificaciones a los clientes.

@startuml
title GYMETRA Booking – Sequence Diagram

actor Cliente
boundary AppMovil as App
control Gateway
control AuthService
control MembershipsService
control PaymentsService
control AccessService
database PostgreSQL

== Registro/Login ==
Cliente -> App : Ingresa credenciales
App -> Gateway : POST /auth/login
Gateway -> AuthService : validarCredenciales()
AuthService -> PostgreSQL : consultar usuario
AuthService --> Gateway : JWT Token
Gateway --> App : JWT Token

== Renovación de Membresía ==
Cliente -> App : Selecciona renovar plan
App -> Gateway : POST /membership/renew (JWT)
Gateway -> MembershipsService : renovarMembresia()
MembershipsService -> PaymentsService : crearOrdenPago()
PaymentsService -> Pasarela : procesarPago()
Pasarela --> PaymentsService : confirmación
PaymentsService -> PostgreSQL : registrar pago
PaymentsService -> MembershipsService : evento pago-confirmado
MembershipsService -> PostgreSQL : actualizar vigencia
MembershipsService --> Gateway : OK
Gateway --> App : Membresía renovada ✅

== Acceso con QR ==
Cliente -> App : Genera código QR
App -> Gateway : GET /access/validate (QR)
Gateway -> AccessService : validarAcceso(QR, JWT)
AccessService -> AuthService : verificar usuario
AccessService -> MembershipsService : verificar membresía activa
AccessService -> PostgreSQL : registrar acceso
AccessService --> Gateway : acceso permitido
Gateway --> App : acceso concedido 🚪
@enduml

  status        : VARCHAR(20) -- ('active','suspended','canceled','expired')

  * payment_id : BIGSERIAL <>
  --
  user_membership_id : BIGINT <>
  amount             : NUMERIC(10,2)
  payment_method     : VARCHAR(30)  -- ('cash','card','mock')
  payment_date       : TIMESTAMPTZ
  transaction_ref    : VARCHAR(150)
  payment_status     : VARCHAR(20)  -- ('pending','confirmed','failed')

}

  * qr_id : BIGSERIAL <>

  status       : VARCHAR(20) -- ('active','inactive','expired')

  * log_id : BIGSERIAL <>

  city      : VARCHAR(100)
  capacity  : INTEGER

' NOTAS DE IMPLEMENTACIÓN EN POSTGRESQL

note left of User
- email UNIQUE
- Index on (email, status)
- Hash password with BCrypt
end note

note right of Membership
- FK: user_membership.membership_id -> membership.membership_id
- Recommended index: (status, duration_days)
end note

note bottom of Payment
- FK: payment.user_membership_id -> user_membership.user_membership_id
- Index: (payment_date, payment_status)
end note

note right of AccessLog
- FKs: user_id, qr_id, branch_id
- Index on timestamp for reporting
end note

Acceso al GYM
  • Como Cliente quiero acceder al gimnasio escaneando un código QR para validar mi membresía.
  • Como Cliente quiero recibir una notificación si mi acceso es denegado para saber el motivo.
  • Como Administrador quiero revisar los registros de acceso (logs) para controlar quién entra y cuándo.
  • Como Administrador quiero poder desactivar accesos en casos diferentes al pago o suspensión de membresía.
Reportes & Administración
  • Como Administrador quiero generar reportes de membresías activas e inactivas para conocer el estado general.
  • Como Administrador quiero ver métricas de ingresos por pagos para analizar el rendimiento económico.
  • Como Administrador quiero consultar estadísticas de accesos al gimnasio para entender la ocupación.
  • Como Administrador quiero exportar reportes en PDF/Excel para auditorías o reuniones.
Sistema (Técnico)
  • Como Desarrollador quiero que el sistema tenga logs centralizados para identificar y resolver problemas rápidamente.
  • Como Sistema quiero aislar el microservicio de pagos para escalar sin afectar otros módulos.
  • Como Sistema quiero registrar accesos en la base de datos por sede para soportar múltiples gimnasios.
  • Como DevOps quiero automatizar despliegues CI/CD para entregar nuevas versiones sin afectar al servicio.
  • Como Administrador del sistema quiero que el sistema gestione backups automáticos de la base de datos para prevenir pérdida de datos.
